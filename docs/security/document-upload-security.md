# VidyaVerse — Document Upload Security

## 1. Supported Formats

Initial supported formats:

- PDF.
- JPEG.
- PNG.

Unsupported formats shall be rejected.

## 2. Initial Limits

- Maximum PDF size: 20 MB.
- Maximum image size: 10 MB.
- Maximum PDF pages: 30.
- Signed URL expiration: five minutes.

Limits shall be configurable.

## 3. Upload Authorization

Before authorizing an upload, verify:

- Authentication.
- Resource ownership.
- Guardian relationship where applicable.
- Account status.
- Subscription entitlement.
- Upload quota.

## 4. Object Storage

Uploaded documents shall use private
object storage.

Object keys shall be generated by
the backend.

Original filenames shall not be trusted
as storage paths.

Public bucket access shall be blocked.

## 5. Signed Uploads

Signed upload authorization shall be
restricted to the intended object key.

Apply supported size and content conditions.

Verify the actual uploaded object before
accepting it for processing.

## 6. Quarantine

Unverified files shall remain quarantined.

Files shall not be processed or made
available for ordinary download until
required security checks pass.

## 7. Security Validation

Validate:

- Actual file signatures.
- File size.
- Supported format.
- Malware scanning results.
- Document page count.
- Image dimensions.
- Decompression limits.
- Parser resource limits.

Reject or isolate unsafe documents.

## 8. Processing Isolation

Document parsers shall operate with:

- Restricted filesystem access.
- Restricted network access.
- Execution time limits.
- Memory limits.
- Least-privilege service permissions.

## 9. Prompt Injection Protection

Document text shall be treated as data.

Instructions embedded in uploaded files
shall not override AI system policies.

Document content shall not grant
additional tool permissions.

AI-generated outputs shall be validated.

## 10. Download Authorization

Every document access request shall
verify resource authorization.

Short-lived signed download URLs may
be issued after successful authorization.

## 11. Retention and Deletion

Uploaded files and derived artifacts
shall follow documented retention policies.

Deletion workflows shall address:

- Original objects.
- Extracted content.
- Derived educational artifacts.
- Temporary processing files.
- Applicable object versions.

## 12. Observability

Track:

- Upload success and failure.
- Rejected file counts.
- Security scanning failures.
- Processing latency.
- Queue age.
- Processing cost.

Do not log private document contents.
